## Stack & conventions
- React 19 + TypeScript 7 + Vite 8 + Tailwind v4 (theme tokens in `src/index.css` `@theme`), Dexie 4 + `dexie-react-hooks` (`useLiveQuery`), React Router 7 with **HashRouter** (needed for GitHub Pages), `vite-plugin-pwa` (offline precache, autoUpdate).
- Recharts 3 is installed (stage 3). The e1RM chart is `src/features/progress/E1rmChart.tsx`, which also has a plain-SVG `Sparkline` for small cards.
- **All weights are stored in kg.** Convert only for display/input with `toDisplay`/`fromDisplay`/`fmtWeight` in `src/lib/format.ts`. Australian locale (`en-AU`), dd/mm.
- IDs: `uid()` from `format.ts` (not `crypto.randomUUID`, which fails on plain-http LAN testing). Seeded exercise ids are slugs (`lat-pulldown`).
- Dark theme, single accent `#b6f23a` (lime). Original design only: no Fitbod branding, art, photos or videos. **One exception, at the user's request (11/2026):** the body map shapes (`src/features/body/bodyShapes.ts`) are traced from Fitbod screenshots the user supplied. The user says Fitbod support allowed this for personal use only, and chose to publish it on the public site anyway. Exercise thumbnails (`ExerciseThumb`) are a crop of the same body map with the primary muscles lit in the category colour (secondary at 40%), front or back by whichever shows the target bigger (`src/features/body/muscleIcon.ts`). Exercises with no muscles fall back to initials. The user asked for muscle symbols instead of initials.
- Screens are mobile-first, max-w-lg, bottom tab bar, a fixed bottom action bar with `pb-safe`.

## Behaviour decisions already made (don't undo without asking)
- **PRs:** an exercise's first-ever session sets a silent baseline (`previous` undefined, not counted). Only records that beat a previous best are celebrated or counted. Deleting or editing a workout calls `rebuildRecords` for the affected exercises.
- The rest timer uses stored timestamps (`endsAt` / `pausedRemainingMs`), never interval counting. `RestAlarm` at app level fires vibrate and beep once per rest. Audio is unlocked on the Log Set tap.
- Editing a set's weight or reps copies the new value to later unlogged sets that had the old value (or no weight). Max Effort sets are excluded.
- Edits on the Workout tab (the ⋯ menu) change the **template**. Edits during an active workout change only that session.
- `NumberField` keeps local text while focused. A controlled value fed straight from Dexie drops keystrokes, so don't change it back.
- `ActiveWorkoutPage` uses a `leaving` ref so its "no active workout, go home" redirect doesn't race navigation to the summary.
- Swipe left (past 40% of the row) removes an exercise from the Workout tab list (changes the template, like the ⋯ menu) or the active workout (that session only). An Undo bar shows for 5 s. `SwipeToDelete` / `useUndo` in `src/components/Swipe.tsx`. The user asked for this.
- Cancelling edit on a workout with no exercises deletes it (for blank past workouts created with +).
- Weekly goal and streak count distinct training days. The current week only adds to the streak once met and never breaks it.
- Exercise history: e1RM counts every working set (warm-ups skipped), including Max Effort singles. Week/Month plot every session; 6 Month/Year plot each month's best. The range opens on the shortest one with at least 2 points, so the first view is a line, not a dot.
- A seeded e1RM record (no `sessionId`, from Fitbod) counts as the PR, labelled "from Fitbod", when it beats everything logged. It has no date, so it isn't charted until the Fitbod import (stage 8). The user chose this.
- Benchmark lifts default to the 5 most-used exercises (`useCount`). Once the user edits them, `Settings.benchmarkIds` holds the pinned list. "Use most used" clears it again.
- Weekly targets: each working set counts **once** toward its exercise's category (push/pull/legs); core/other count nowhere. The per-muscle breakdown uses SPEC's primary 1 / secondary 0.5, so it doesn't sum to the group total (a note on screen says so). Summing muscle credits instead would make one bench set count ~2 push sets. The user chose this.
- Each group counts toward the overall % only up to its target, so extra push can't hide missing legs. Sets go into the week their workout **started** in.
- Targets are edited from the Targets tab ("Edit targets") for now. My Plan (stage 7) should link to the same editor, not duplicate it.
- Recovery: dose per muscle per workout = 1 per primary set + 0.5 per secondary. Hours needed = 48 up to dose 3, rising evenly to 96 at dose 12+. With several recent workouts, the least recovered one counts. Looks back 14 days, using the session's `endedAt`.
- A manual recovery value (`recoveryOverrides`) is a starting point that keeps rising at the muscle's normal pace. It's dropped once a workout that trains that muscle **finishes after** it was set. The user chose this over a value that stays frozen.
- Body map colours **fade** with recovery %: red at 0% → amber at 50% → lime at 90%+ (fresh), mixed with CSS `color-mix(in oklab, …)` using the `--color-danger` / `--color-warn` / `--color-accent` tokens. The % is always shown as text too. The user first chose three fixed bands, then asked for the fade.
- Recovery maths clamps "time since" at 0, because `useNow` ticks once a minute and a just-saved workout or override can look slightly in the future.
- No login screen. The user asked for one, then dropped it: on a static GitHub Pages site with a public repo, a login running on the phone can't hide anything (the code and shapes are public anyway), and all data stays on the phone already.
- Templates stay the default: a split day with a saved template uses it. Generated workouts are for days with no template (e.g. Upper/Lower), "Generate a fresh workout" and "Pick muscle groups". The user chose this over Fitbod-style daily generation.
- A generated workout isn't a template: `suggestedTemplate()` builds it on the fly (deterministic), and picking or editing it stores it in `settings.generated` with `selectedTemplateId = 'generated'` (`GENERATED_ID`). `saveTemplate` routes edits there. `finishWorkout` clears both.
- Day due = done least recently; ties go to the freshest muscles (`currentRecovery()`). Generated split days skip minor muscles (traps, lower back, forearms, adductors, abductors) so they don't pull in rarely used isolation moves. "Pick muscle groups" can still target them.
- Generator scoring: preference ×2 + log10(useCount+1) + freshness ×2, a rotation bonus/penalty for last time's exercises (low +1.5 / mid −0.75 / high −3), and −1.75 per already-picked exercise sharing a main muscle. About 7½ min per exercise, 3-10 exercises.
- Progression is **pre-filled** into the sets (user's choice), with a note: "↑ +2.5 kg", "+1 rep" or "−10% lighter" (`ActiveItem.progress`, formatted by `fmtProgress` in the user's units). Rep range: per exercise (`repMin/repMax`) or the goal's default (Build Muscle 8-12, Strength 4-6, General Fitness 10-15). Weight steps default dumbbell 2 / cable+machine 2.5 / barbell 2.5 / plate-loaded 5 kg, editable in My Plan. Max Effort items keep their ramp.
- Warm-ups (toggle): one set at about 50% weight × 10 before the first **loaded** exercise for each main muscle (not before Max Effort). Shown as "W", and logged with `isWarmup` so they're excluded from stats.
- My Plan leaves out SPEC's cardio, stretching, circuits/supersets and focus exercises until they do something (user's choice).
- Fitbod import: a Fitbod workout is skipped if this app already has any workout that day (so re-importing is safe). Imported sessions get Push/Pull/Leg Day names when ≥60% of working sets are in one group, else "Workout". Duration = first-to-last set + 2 min, or 3 min per set (20-120) when sets share one timestamp. Calories are estimated. Unmatched names default to "add as new" (category 'other', no muscles; the user sets those later). Matched exercises keep their seeded `useCount`; new ones get the number of workouts they appear in.
- After import, seeded PR records (no `sessionId`) for the imported exercises are deleted and `rebuildRecords` replays everything. `lifetimeOffset` is reduced by the imported workouts/volume/calories, never below 0. The user chose this so totals stay matched to Fitbod.
- Updates: `registerType: 'prompt'` + `UpdateToast`. "Reload" calls `updateSW(true)`, which is safe mid-workout because state is in IndexedDB.
- Strength score: 9 sub-groups (Chest, Shoulders = all delts, Triceps / Back = lats+upper back+traps+lower back, Biceps / Quads, Hamstrings, Glutes, Calves). Forearms, abs, obliques, adductors and abductors have no score. An exercise counts toward a sub-group if any of its **primary** muscles is in it. Exercises not done in the last 4 weeks are skipped, not counted as zero.
- Scores are computed as of each **week start** (SPEC: recalculate weekly), so a PR shows up in the score the following week. The trend compares with 4 weeks earlier. Nothing is stored; it's all recomputed from sets.
- Muscle volume: a set's kg counts fully for sub-groups its primary muscles touch, and half for those only its secondary muscles touch (once per sub-group). The user chose this.
- The Workout Report opens from both Settings and "See full report" on Body > Results. Share uses `html-to-image` and leaves out `data-noshare` elements and chart tooltips. In the Claude browser pane, capture hangs while the pane is hidden (requestAnimationFrame is paused). That's not an app bug.

- Pull Day's "+1 more" exercise from SPEC §7 is unknown; it was left out. Push Day, Seated Leg Curl and Leg Press weights start blank.
